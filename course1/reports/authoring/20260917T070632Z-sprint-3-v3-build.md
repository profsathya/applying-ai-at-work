**Material authoring choices:**

- **Storage sprint 15**, the next unused number above the current maximum (14), so V3 is unambiguous against `sprint-3`, `sprint-7` (V2), and the retired `sprint-10`/`sprint-11` content. The source's "confirm the folder" note asked not to guess between `sprint-6` and `sprint-7`; both are occupied by other modules, and the request was for a separate V3, so neither was reused.
- **Positions 1 to 7**, module header first, matching the repository's actual convention in `sprint-7` and `sprint-8` rather than the source's 1-to-6 note, which did not account for the header.
- **Presentation.** Introduction uses `page_presentation: reading`. The Dojo Lab uses `delivery_mode: guided_assignment` with `presentation: reading` and one response task mapped to `## What changed, and why`, so the response sits immediately after its instructions and no generic goal panel appears. The Stakeholder Map and Concept Check are standard layouts; a real `learning_goal` was added to each artifact that renders the goal panel, replacing the renderer's circular default ("Check your understanding of Sprint 3 Concept Check before moving forward").
- **Visual.** One illustration, `assets/workplace-handoff.webp`, reused from the approved Sprint 1 pilot in the Introduction, with alt text, an AI-generation disclosure caption, and provenance recording the reuse. It was chosen because this sprint's worked example continues Sprint 1's account-handover situation. No new imagery was generated and no image quota was applied; the other five items are text, tables, and worked examples where a picture would add nothing.
- **Continuity verified, not assumed.** The map's worked example claims it continues Sprint 1's account lead. `course1/sprints/sprint-14/the-problem-frame.md` ends its worked example with "Start with the account lead" and lists "Nobody has tried to fix this before. Who could tell me: the account lead" as an unverified assumption, which is the same assumption the V3 assumption-block example uses.
- **ASCII.** All seven artifacts are pure ASCII, per the source's BUILD rule. `homepage.yaml` keeps the middle dot already used throughout that file for `nav_meta` consistency.

## Findings

**Resolved during this build:**

1. **Mobile overflow.** The source directed a four-column chart (Field / Ask yourself / Example answer / Trap to avoid). Rendered, it failed the 390px overflow check on the Stakeholder Map. It was rebuilt as seven `###` field sections, each with the same three labelled bullets, which the source's own prose already used. No content was dropped. The re-check passes.
2. **Clipped AI prompts.** The Dojo Lab's three prompt code blocks were wrapped at roughly 78 columns and were visibly cut off inside the `pre` block at 1280px, where participants must read and copy them. Re-wrapped to about 68 columns; all three now display in full at desktop width.
3. **Generic goal panels.** Added real `learning_goal` values to the four artifacts that render one.
4. **Cross-reference drift.** After the table became sections, the Stakeholder Conversation's pointer to a "row in your chart" was corrected to "field in your map".

**Deferred, with reasons:**

5. **Template links are placeholders.** `STAKEHOLDER-MAP-TEMPLATE-DOC-ID` and `STAKEHOLDER-VALIDATION-REPORT-TEMPLATE-DOC-ID` must be replaced before release. Creating Google Docs is outside this session. Steps are in `course1/sprints/sprint-15/templates/README.txt`; the `.docx` originals are beside it. Publishing as-is would give participants two dead links.
6. **Rubrics.** Not authored, per the source's instruction that the publish script does not push rubric blocks. The 35, 50, and 10 point items need rubrics built in the Canvas UI.

**Needing a human decision:**

7. **The source's typing fix cannot be applied as written.** It asks that the AI-activity items stop being typed `quiz`. `canvas_sync/schema.py` restricts `delivery_mode: ai_activity` to source `type` `quiz` or `discussion`, and `canvas_sync/push.py` `canvas_type_for()` already publishes every AI activity to Canvas as an `assignment`. So the Canvas-side type is correct today and only the source-side label is odd. V3 uses `discussion` for the Stakeholder Conversation and `quiz` for the reflection, matching V2. Changing the allowed source types is a `canvas_sync/` change and belongs to the maintainer.
8. **Duplicate item title across modules.** `Dojo Lab: test, widen, choose` is also the title of a Sprint 1 item (`course1/sprints/sprint-14/dojo-lab-test-widen-choose.md`), as the source anticipated. Slugs and artifact IDs differ, so validation is clean, but two identically titled items will appear in Canvas search and the gradebook.
9. **Retired "Goal Plan" wording elsewhere.** `course1/homepage.yaml` still says "goal plan" in the Sprint 3 and Sprint 4 reflection lines for the existing `sprint-3`, `sprint-7`, and `sprint-5` modules. Those lines describe other modules, so they were left alone rather than edited from inside a V3 build. V3's own copy uses Problem Frame throughout.

No other issues found in this scope. This is not a claim of exhaustive certainty.
