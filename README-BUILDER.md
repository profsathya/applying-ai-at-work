# Canvas Course Builder (Applying AI at Work)

Autonomous Ralph-loop system for building canvas courses directly from this repo's design docs. The builder reads `course1/design/` and `course2/design/` plus the shared `context/` directory, plans a PRD, and pushes every assignment, page, discussion, and quiz to canvas via the REST API. Markdown is the source of truth; per-course manifests map local files to canvas IDs.

**This supersedes the legacy iframe pattern.** See `archive/legacy-iframe-template/WHY-ARCHIVED.md`.

## One-time setup (first install in this repo)

1. Unzip the builder scaffold on top of this repo (you've already done this if you're reading this).
2. Run the migration script from the repo root:
   ```
   ./migrate.sh
   ```
   This moves design docs into `course1/design/` and `course2/design/`, archives the legacy template, writes a decision-log entry, and resolves the "which delivery platform?" open question.
3. Review and commit:
   ```
   git diff --stat
   git add -A
   git commit -m 'feat: adopt canvas-course-builder, restructure for canvas-native delivery'
   ```
4. Install Python deps:
   ```
   python -m venv .venv
   source .venv/bin/activate
   pip install -r canvas_sync/requirements.txt
   ```
5. Install Claude Code if not already installed:
   ```
   npm install -g @anthropic-ai/claude-code
   ```
6. Create two empty canvas course shells in De Anza's instance (one for Course 1, one for Course 2). Note their course IDs.
7. Configure credentials:
   ```
   cp .env.example .env
   ```
   Edit `.env`:
   - `CANVAS_API_URL` = De Anza canvas URL
   - `CANVAS_API_TOKEN` = your personal access token
   - `COURSE1_CANVAS_ID` = the course 1 shell ID
   - `COURSE2_CANVAS_ID` = the course 2 shell ID
8. Smoke test:
   ```
   COURSE1_CANVAS_ID=<id> python canvas_sync/canvas_client.py
   ```
   Should print: `Connected to course <id>. Found N modules.`

## Build Course 1

```bash
./ralph.sh --verbose
```

Ralph iterates until Course 1 is fully in canvas. Each iteration builds one artifact. Walk away; come back to a built course.

## Build Course 2

```bash
TARGET_COURSE=course2 ./ralph.sh --verbose
```

## Day-to-day after the initial build

The Ralph loop is for initial builds only. Ongoing edits use slash commands in a single Claude Code session:

### Add one artifact

```bash
claude -p "/add-artifact add a 20-point reflection to course 1 week 5 called 'Stakeholder mid-check'"
```

### Push a manually-edited MD file

```bash
claude -p "/sync course1/sprints/sprint-2/stakeholder-interview.md"
```

### Reconcile drift after direct canvas edits

```bash
claude -p "/reconcile course1"
```

## Grading

Lives in `n8n/`, separate from the build runtime. See `n8n/README.md`. Flow: canvas submission webhook -> Claude API with SRL-grounded feedback prompt -> HITL review queue (Google Sheet or n8n human-approval node) -> instructor approves -> grade posted to canvas -> audit log.

## Troubleshooting

**Migration complains about missing files:** the migrate script is idempotent but expects the base repo structure. Make sure you're running from the repo root and that `context/decision-log.md` exists.

**Loop halts with "scaffold incomplete":** unzip didn't complete, or a file was accidentally deleted. Check the error, restore, rerun.

**Loop halts with "planner produced invalid PRD":** read `course1/progress.md` for schema errors. Delete the PRD and rerun to let the planner retry.

**Canvas push 401:** token is invalid or lacks scope. Regenerate.

**Canvas push 404:** wrong course_id in `.env`. Verify in the canvas URL.

**Artifact landed in wrong module:** the planner produced a module name that doesn't match what you expected. Check the PRD item's `module` field and edit if needed, then rerun /sync on that file.

## Design rationale

See `context/design-principles.md` for the pedagogical principles and `context/decision-log.md` for the builder-adoption decision. A summary of the technical choices:

- **Canvas-agnostic MD is the source of truth.** Canvas IDs live only in manifests so the same content can be pushed to multiple shells (sandbox, production, cloning to a new term).
- **Canvas wins on drift.** Once live, direct canvas edits take precedence. `/reconcile` pulls them back.
- **One artifact per BUILD iteration.** Ralph's determinism: predictable failures beat unpredictable successes.
- **Schema validator is a hard gate.** Catching errors before canvas is cheap; catching them from confused participants a week later is expensive.
- **No HTML in MD.** Markdown stays portable; canvas-flavored HTML is a conversion concern, not a content concern.
- **Frameworks present, not labeled.** Participants experience the frameworks; they do not memorize them. The schema validator does not enforce this, but the subagent prompts do.
