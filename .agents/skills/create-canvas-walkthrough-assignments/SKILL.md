# Create Canvas Walk-Through Assignments

Turn selected course material into new, interactive AI-guided assignments. The reference transformation is [`Brainstorm your list`](../../../course1/sprints/sprint-14/brainstorm-your-list.md) to [`Brainstorm Your List AI-guided activity`](../../../course1/sprints/sprint-15/brainstorm-your-list-ai-guided-activity.md): retain the learning task, turn its directions into a walk-through with participant work and contextual help, and add optional formative AI feedback. Study both artifacts and the rendered new activity before designing a different one. Adapt the structure, prompts, document handling, and feedback to each source; do not copy Brainstorm's content or endpoint.

Trigger on instructor wording such as “create this as a Canvas walk-through assignment,” “make Sprint 3 Stakeholder Map a Canvas walk-through assignment,” or “create the following assignments as Canvas walk-through assignments.” Accept a Canvas URL, title, module location, or ordinary-language list, with an optional Google Doc, DOCX, ZIP, or other source for each item. Resolve names and linked sources autonomously when possible; do not require the instructor to supply internal IDs or a structured input file.

The original Canvas page or assignment and its linked document remain intact. Each result is a **new module item immediately below its source item** in the same live module. Do not replace, rename, migrate, or edit the original. Treat a named example as a design reference until the instructor actually requests its conversion.

## Map the source and placement

1. Inspect the live Canvas module and read the source item itself, its linked instructions or assignment, rubric, publication and submission settings, and nearby items. Resolve duplicate titles before drafting. Record the exact module item to follow. Use the read-only `inspect-canvas` workflow where helpful. Do not infer the live module from a storage folder's sprint number.
2. Read any linked or supplied document through [Document Intake](../../../docs/DOCUMENT_INTAKE.md). A Google Doc `/copy` link points to a working template; read the underlying template when access permits. If it cannot be read, ask for an accessible source before adapting its contents. Keep source captures under `.source-intake/` and record provenance beside document-derived Markdown where required.
3. For each requested conversion, record the source item, document, existing participant task, evidence or submission requirement, independence or AI restrictions, and the intended new activity. Identify the step at which formative AI feedback can help without doing the participant's work. If the source says to work without AI, preserve that first pass and place feedback only after it. If the new activity would contradict a grading or submission rule, resolve that design question with the instructor. Ask only when a consequential ambiguity cannot be resolved from the available sources.
4. Give the new activity its own title, slug, artifact ID, Markdown file, and Canvas identity. Choose an adjacent position from the **live** module order and preserve the relative order of all existing items. In a batch, keep a source-to-new-item map and account for earlier planned insertions when calculating later positions.

## Design and build the new activity

- Follow [Authoring and Review](../../../docs/AUTHORING.md) and [Authoring Presentation](../../../docs/AUTHORING_PRESENTATION.md). Keep the original learning task and evidence recognizable. Break a long page or document into a coherent sequence of brief teaching, participant action, response capture, contextual help, an explicit request for AI feedback, and revision. Include a complete path through the activity without requiring AI feedback. Feedback is formative, not an AI grade. Do not invent new points, due dates, rubrics, or completion requirements.
- Use `delivery_mode: guided_assignment` and the supported renderer when it fits. The current Brainstorm `interleaved` presentation and `brainstorm-list-v1` feedback contract are specific to that activity; do not reuse their endpoint or task protocol for unrelated work. If a source needs an interaction or feedback contract the renderer lacks, implement the reusable support and review that code with the new activity. For a new AI endpoint, read `services/course-ai/README.md` and the relevant Netlify AI Gateway guidance before choosing a model. Keep feedback criteria server-side; send only the participant response needed for the requested checkpoint.
- Decide how the new activity relates to the original submission. A source may require a continuing Google Doc or a file upload; do not silently replace that evidence with a text box. The new activity may guide and give feedback on work that remains in the document. State where the participant keeps the work and what, if anything, they submit in Canvas. Browser drafts, copying, and AI feedback do not submit work.
- Keep the Canvas embed free of redundant generic learning-goal or submission panels and links back to the assignment already open. Give participants a path to continue if feedback or clipboard access fails. Preserve accessible labels, keyboard operation, and clear privacy guidance for information sent to the feedback service.

## Review, then publish when authorized

1. Draft new Markdown under the target course's `sprints/` tree; do not edit the source artifact or design documents. Use `publish: false` for a new preview until the instructor requests publication. Render the complete experience and inspect desktop and mobile views, feedback, saved drafts, and the Canvas submission path. Distinguish editorial checks from participant testing.
2. Review substantive text with `reviewing-course-text`. Route through `maintain-homepage` if the course has `homepage.yaml`; an unpublished draft need not gain a public homepage link. Run `canvas_sync/schema.py --artifact` for each new file and the required final validation. Save the authoring review record from `docs/AUTHORING.md`, including source-to-new-item mapping, provenance, preview, and the planned insertion point.
3. If the instructor explicitly requested a live Canvas creation in the current turn, follow `sync` and the protected production workflow after validation; do not ask them to repeat that authorization. Otherwise report the reviewed preview and ask before a Canvas write. Immediately before publishing, re-read the live module order and verify each anchor still exists. After publishing, check that each new item sits immediately after its source and that other items keep their relative order. Report the new artifact(s), what was adapted, validation, live or draft state, and any unresolved decision. Canvas writes require explicit confirmation in the current turn under `AGENTS.md`.
