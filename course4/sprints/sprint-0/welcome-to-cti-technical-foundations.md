# Welcome to CTI Technical Foundations

This course prepares you to understand code well enough to work with modern AI coding tools.

It is not a replacement for a full programming course. You will not learn every Python feature, every syntax detail, or every pattern a professional developer uses. You will learn enough to read examples, follow program behavior, explain what generated code is doing, and notice when a program needs more careful thought.

## Why This Matters

AI tools can produce code quickly. That speed is useful only when you can judge the result.

If you cannot read the code, you cannot tell whether it solves the right problem. If you cannot run it, you cannot observe what it actually does. If you cannot explain where it might fail, you cannot use it responsibly.

This course helps you build the missing middle:

- Enough programming vocabulary to follow examples.
- Enough confidence to write and test small pieces yourself.
- Enough judgment to ask better questions of AI tools.
- Enough project awareness to enter 202A ready for implementation work.

## How This Course Works

Each week has four kinds of work:

1. **Concept pages.** These explain the programming ideas you need for the week.
2. **CodeChecks.** These are small coding tasks. They are meant to be simple enough to attempt without AI.
3. **LLM analysis labs.** These use fixed starter code so everyone studies the same sample.
4. **Projects.** These ask you to build or extend something concrete using the concepts from the week.

The course de-emphasizes syntax drills. Syntax matters, but it is not the main target. The main target is understanding constructs, behavior, reliability, and how to stay in control when code is generated quickly.

## What To Do When You Get Stuck

Use this order:

1. Read the error message or unexpected output slowly.
2. Identify the smallest part of the program that could be causing the issue.
3. Add a print statement, a test, or a short note explaining what you expected.
4. Ask a peer, instructor, or AI tool for a narrow explanation.
5. Rewrite your explanation in your own words before changing more code.

Getting stuck is part of technical work. The skill is not avoiding confusion. The skill is slowing down enough to find what the program is telling you.
