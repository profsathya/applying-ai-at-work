# LLM Analysis: Starter Flask Application

## Purpose

Analyze a starter Flask application and use AI to help with project work after you define the requirements.

Your instructor will provide the starter application. It may be a video streaming app, public chatroom, or another small web application. Everyone should use the same starter code.

## Part 1: Define Requirements

Before prompting AI, write a short requirements note:

1. What does the app do?
2. Who uses it?
3. What is the minimum useful version?
4. What data does it store or display?
5. What should not be included yet?
6. What would make the app unsafe, confusing, or unreliable?

## Part 2: Read The Project

Identify:

- The main Flask app file.
- The route functions.
- Templates or static files, if present.
- Any data file or database.
- How to run the app locally.
- What happens when an error occurs.

## Part 3: Create A Context File

Create a short project context file or equivalent note for AI:

```text
Project: Starter Flask app
Goal: Build a minimum useful feature
Current files:
Rules:
Do not:
Validation command:
Definition of done:
```

This context is what keeps AI from inventing a different project.

## Part 4: Build Or Design A Feature

Choose one:

- Add a simple form.
- Add a list view.
- Add a data validation check.
- Add a basic search or filter.
- Add logging for an important event.
- Add a small test for one route.

If your instructor includes deployment, follow the current instructions for Heroku or the approved deployment target. Deployment is secondary to understanding the app and feature.

## Submission

Submit:

- Your requirements note.
- Your starter app structure explanation.
- Your context file or equivalent project brief.
- The AI prompt you used.
- The feature you built or designed.
- Evidence that you ran, tested, or debugged the app.
- One paragraph explaining what you would review before publishing or sharing the app.
